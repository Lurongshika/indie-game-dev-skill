# 美术方向与游戏画面

适用：视觉探索、风格统一、角色/环境、资产制作和画面评审。将“精致、氛围感”等形容词变成可复现规则。

## 从体验到风格页

确定情绪、镜头距离、观看节奏、玩法辨识与产能。少量参考图逐张说明借鉴的是配色、形状、材质、构图还是光照；注明来源，参考图不自动成为可商用资产。

比较候选风格的角色朝向、动作/帧数、模型/绑定、复用率、特效、修改速度和硬件成本。像素风、手绘、低多边形、写实都可能昂贵，不能按名称判断便宜与否。

最小风格页按需写入：

- 视觉关键词、应避免的特征和形状语言。
- 主/辅助/强调色的用途，主体与前中后景的明度层级。
- 比例、轮廓、材质/线条，交互物和背景的辨识方式。
- 镜头、构图、光照方向，UI 与世界的视觉联系。
- 2D 的像素密度、尺寸、枢轴、图层、动画节奏；或 3D 的尺度、坐标、拓扑、材质、骨骼、LOD，只选相关项。
- 源文件→导出→引擎的命名、压缩、过滤与导入约定。

先做实际游戏镜头样张：主角、典型环境、交互物/威胁、必要 VFX 与 HUD 同屏。概念图不能验证运动、遮挡和特效叠加后的辨识度。

## 生产管线与预算

资产表记录 ID、用途、规格、动作/变体、依赖、作者/来源、许可状态、源/导出文件、负责人和完成条件。区分占位、定稿、已集成、运行时验收。

批量前让代表性资产走完草图/灰模→确认→制作→导出→导入→实际镜头检查。提前确定方向、比例、材质、透明边缘、枢轴、骨骼/动画和碰撞等交接要求。

按目标设备实测分配纹理/显存、材质、光源、粒子、动画和加载预算，不复制其他游戏的多边形/贴图上限。先诊断瓶颈再优化。

## 画面评审

1. 玩家能否一眼看见自己、目标、威胁和交互区域？检查灰度、缩小与运动情况。
2. 轮廓、明度、颜色和细节密度是否形成合理层级？
3. VFX 是否表达结果，有无遮住操作与关键预警？
4. 同类资产的比例、光向、材质和像素密度是否一致？
5. 目标机帧时间、内存和加载是否达到项目目标？

按操作辨识、风格一致、装饰细节排序，给最小修改，用同镜头同条件比较。不在不了解玩法时擅自更换用户风格。

依据：[Valve Character Art Guide](https://help.steampowered.com/en/faqs/view/0688-7692-4D5A-1935) 的轮廓、明度与焦点原则；[Unity 2D art style reference](https://docs.unity.com/en-us/engine/6000.5/manual/unity2d/2d-game-development/2d-game-art-syle-reference) 的表现类别；[Pre-Production](https://www.gamedeveloper.com/game-platforms/what-you-should-take-out-of-pre-production) 的资产交接思路。Dota 2 英雄限制不推广到其他游戏；规格和评审表为综合建议。
