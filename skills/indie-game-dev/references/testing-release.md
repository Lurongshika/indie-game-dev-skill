# 试玩、回归与发布准备

适用：原型评估、里程碑验收、构建和交付。玩法体验、功能、性能与平台检查分别记录。

## 试玩与问题记录

写本轮要回答的问题，例如“玩家无需口头提醒能否找到首次交互”。记录版本、目标玩家、起始状态、观察动作和通过/调整标准。少量探索性试玩用于发现问题，不包装成统计结论。

观察行为、停顿和理解；避免边指导边声称易用性通过。结合访谈区分偏好、理解障碍、缺陷与体验问题。每轮修最影响体验的问题，再以相同条件复查。

问题记录构建/设备、复现步骤、预期/实际、频率、影响、证据、负责人和验证状态。按数据丢失、进程阻断、核心规则、可用性、表现等实际影响排序；低复现率不等于低严重性。

## 候选构建清单

按项目范围取舍：

- 在可用的干净环境安装/解压启动，不依赖开发机绝对路径和缓存。
- 从新游戏/继续走到当前设计终点，覆盖失败、重试、退出和重进。
- 需要存档时检查保存/恢复、缺失/损坏文件，以及承诺支持的旧版本。
- 验证目标输入、暂停/失焦、设置保存、UI 缩放、文本和目标语言。
- 在目标设备代表性/压力场景检查帧时间、内存、加载，说明覆盖范围。
- 确认资产/字体/音频来源与许可记录；平台 SDK、隐私/联网行为、商店支持声明与构建相符。
- 记录版本、源码状态、引擎/依赖、构建步骤、已知问题和恢复方式。

无联机/成就/付费/云存档时不新增这些要求。审核、素材尺寸、活动日期和政策查当前平台官方文档，不将易变规则固化在 skill。

按用户授权交付本地可玩构建和说明；对外上传、发布、改价格或账户操作取决于对应授权和权限。检查表不代表这些动作已获授权。

报告实际运行的场景、设备与结果，区分静态、自动化和人工试玩；不能运行时给具体待验证项。发布后先修数据丢失、启动崩溃和阻断，修复构建避免混入大型新功能。

依据：[Game Accessibility Guidelines](https://gameaccessibilityguidelines.com/full-list/) 的访问性检查入口与 [Steamworks Localization](https://partner.steamgames.com/doc/store/localization?l=english) 的语言支持区分；其余流程为综合工程实践，不是商店审核保证。
