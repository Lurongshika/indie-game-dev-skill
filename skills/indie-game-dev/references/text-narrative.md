# 文本编辑、叙事与本地化

适用：UI 文案、物品/技能、任务、对白、分支、校对和多语言。先确认是润色、重写、续写还是结构修复。

## 保留语义和实现约定

读取世界观、人物关系、时间线、术语、内容边界和格式。建立简短术语/口吻表；无叙事需求时不强加剧情。

润色保持事实、条件、奖励数值、选项后果和人物意图。改变设定/规则的建议单独标注；保留变量、控制标签、占位符和资源键。规则歧义先核对实现，不能只追求顺口。

| 文本 | 编辑重点 | 验收 |
|---|---|---|
| 按钮/菜单 | 动作明确、术语一致 | 能理解，布局不溢出 |
| 物品/技能 | 条件、效果、单位、代价 | 与实现/数值表一致 |
| 任务/教程 | 当前目标、线索、完成反馈 | 玩家知道可做什么 |
| 对话/旁白 | 口吻、信息节奏、场景目的 | 朗读及游戏内节奏检查 |
| 商店文案 | 准确描述已实现体验 | 不承诺不存在的支持/功能 |

## 可导入数据

复用已有 CSV/JSON/表格/叙事脚本格式。无格式时可参考字段：

```text
id | source_text | speaker | context | condition | effects | next_id
   | locale | translation | layout_limit | status
```

按需求删减，选择一行一语言或一列一语言。ID 稳定唯一，改文案不随意改键。布局限制记录具体容器/行数/展示条件，不能仅凭字数保证适配。

小范围交付原文、修改、理由；大量编辑交付可导入文件和变更摘要。新创作注明创作部分，不声称来自用户原稿。

## 分支与工具

节点记录进入条件、选项、状态变化、后继和终止方式。选项表达玩家意图；分支合流时保留应有后果，并估算新增写作、翻译和测试成本。

检查不可达节点、缺失跳转、无出口循环、互斥条件、重复奖励、状态未初始化和读档重入。按关键状态组合/结局覆盖，不承诺穷举所有路径。

已有工具能满足时优先复用。ink 支持 knots/stitches、choices、diverts、条件与变量；引入前确认运行时集成、作者预览、存档和本地化，不为几句线性对白自动增加依赖。

## 本地化

提取玩家可见文字，为翻译提供语境、说话者、术语和命名占位符；避免源语言碎片拼句，复数/性别等交给所用语言系统。保护 `{player_name}` 等标记。

检查缺失键、语言回退、占位符一致、特殊字符、目标字形、换行、长文本、混合数字、字幕和语言切换；目标语言需要 RTL 时在引擎验证。伪本地化暴露布局问题，不能代替母语校对和语言 QA。

把游戏文本、图片文字、字幕/配音、成就与商店页分别列预算和状态。商店翻译完成不代表游戏支持该语言；按需求、容量和反馈选择语言。

依据：[Writing with ink](https://github.com/inkle/ink/blob/master/Documentation/WritingWithInk.md)、[Godot Internationalizing games](https://docs.godotengine.org/en/stable/tutorials/i18n/internationalizing_games.html)、[Steamworks Localization](https://partner.steamgames.com/doc/store/localization?l=english)。编辑表和字段为综合模板；API 按版本复查。
