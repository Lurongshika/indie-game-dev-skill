# UI 与 UX

适用：菜单、HUD、物品/技能、设置、引导与无障碍。先围绕玩家要完成的动作设计，再确定外观。

## 流程与状态

列出入口、操作、结果、返回/取消、失败恢复。覆盖项目有关的首次启动、继续、暂停、设置和结算；HUD 优先显示当前决策所需信息。

背包操作示例：

| 状态 | 可见信息 | 可执行动作 | 转移/反馈 |
|---|---|---|---|
| 空背包 | 空状态说明 | 返回 | 焦点能到达返回按钮 |
| 已选物品 | 名称、数量、说明 | 使用/丢弃/返回 | 成功后更新数量和反馈 |
| 不可使用 | 禁用动作及原因 | 选择其他物品/返回 | 不只靠颜色表达禁用 |
| 操作失败 | 原因与恢复方式 | 重试/返回 | 不重复扣除物品 |

补充确实存在的加载、确认、输入切换或断线状态；没有异步操作时不虚构加载流程。

## 布局和组件

先低保真流程/线框，再按需高保真。交付参考视口、宽高比策略、安全区、约束、缩放、滚动区域和长文本行为。

建立少量样式：文本角色、间距、颜色语义、面板、按钮、图标和动效。按钮按需包含默认、悬停、焦点、按下、禁用、选中；焦点不等于鼠标悬停。

用容器/约束/锚点表达布局关系。像素风明确整数缩放、字体及 UI 与世界像素密度关系。不要给所有设备套固定字号和热区尺寸；根据显示距离、输入和实际测试确定。

## 输入、反馈与可读性

- 按目标平台支持键鼠/手柄/触屏；手柄定义默认焦点、方向导航、返回和弹窗关闭后的焦点恢复。
- 提示读取当前按键映射，输入切换后更新；不把“按 E”写死到图片和译文。
- 暂停/模态窗口管理输入归属，避免操作穿透；关闭后恢复合理状态。
- 危险的游戏内操作按需确认或提供恢复，避免高频普通操作不断弹窗。
- 成功、失败和不可用有可理解反馈，关键信息按需组合文字、视觉和声音。
- 检查动态背景对比、字形覆盖、字号调节、色觉差异、字幕和动效负担；用形状/文字补足颜色信号。

[对比度指南](https://gameaccessibilityguidelines.com/provide-high-contrast-between-text-ui-and-background/) 提供文字/UI 对背景约 4.5:1 的参考；这不等于整体游戏通过无障碍认证，也不能代替动态场景检查。

## 验收与交付

测试目标中的最小屏幕、不同宽高比、缩放、中文/长译文、重映射和目标输入。观察玩家是否能找到动作、看懂结果并返回。静态稿需标注引擎内待验证项，不宣称运行适配通过。

交付按需选择流程图、状态表、线框/原型、组件规格、资源命名与验收场景。

依据：[Game Accessibility Guidelines](https://gameaccessibilityguidelines.com/full-list/)、[Godot Size and anchors](https://docs.godotengine.org/en/stable/tutorials/ui/size_and_anchors.html)。状态表与组件流程为综合模板。
